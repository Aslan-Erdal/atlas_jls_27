Chapitre 6 · Java SE 27 Edition

Noms

Comment le compilateur sait à quoi renvoie chaque nom du programme : où une déclaration est visible, quand une autre la masque, comment un nom ambigu comme a.b.c est classé, et qui a le droit d'accéder à quoi.

Source : JLS SE 27, chapitre 6 Sections : 6.1 à 6.7

§6.1Déclarations

Une déclaration introduit une entité dans le programme et lui donne un identifiant, qu'on peut ensuite utiliser dans des noms. Entités déclarables :

Organisationmodule (§7.7), paquetage (§7.4), type ou membre statique importé (§7.5)
Typesclasse ou interface de plus haut niveau, membre, locale ou anonyme ; enum ; record ; paramètre de type
Membreschamp, méthode, constante d'enum, composant de record (et ses champ et accesseur implicites)
Variables locales au sens largeparamètre de méthode, de constructeur, de lambda, paramètre d'exception, variable locale, variable de motif

Les constructeurs (§8.8) sont aussi introduits par des déclarations, mais ils utilisent le nom de leur classe au lieu d'introduire un nouveau nom.

Conventions de nommage

La spec recommande des conventions. Elles ne sont pas obligatoires, mais elles évitent presque tous les cas d'obscurcissement du §6.4.2.

Un domaine qui contient un tiret ou un mot-clé est adapté : mon-site.fr devient fr.mon_site, et un composant qui commence par un chiffre prend un _ devant.

§6.2Noms et identifiants

Un nom désigne une entité déclarée. Il est simple (un identifiant, x) ou qualifié (un nom, un point, un identifiant : java.util.List). Mais tous les identifiants ne sont pas des noms. Ne sont pas des noms, donc pas soumis aux règles de portée de ce chapitre :

  • l'identifiant qui déclare une entité (le x de int x;) ;
  • les étiquettes de break / continue (§14.7) ;
  • l'identifiant après le point dans un accès de champ sur une expression primaire (f().x, super.x) ;
  • l'identifiant après le point dans un appel de méthode qualifié par une expression (f().m()) ;
  • les noms d'éléments dans une annotation (@Retention(value = …)).
Java
class Test {
    int x;
    void m() {
        x = 1;                      // x : nom simple
        this.x = 2;                 // x : identifiant après un primaire, pas un nom
        java.util.List<String> l;   // java.util.List : nom qualifié
        boucle: for (;;) break boucle;   // étiquette : pas un nom
    }
}

§6.3Portée d'une déclaration

La portée d'une déclaration est la partie du programme où l'entité peut être désignée par un nom simple, à condition qu'elle ne soit pas masquée. Une déclaration est « en portée » en un point si ce point est dans sa portée.

DéclarationPortée
Classe ou interface de plus haut niveautoutes les unités de compilation du paquetage
Type importé (§7.5)l'unité de compilation qui contient l'import
Membre (champ, méthode, type membre)tout le corps de la classe, y compris avant la déclaration et dans les classes imbriquées
Paramètre de méthode, constructeur, lambdatout le corps
Paramètre de type d'une classela section des paramètres de type, la superclasse, les superinterfaces et le corps
Paramètre de type d'une méthodela déclaration de la méthode entière, y compris type de retour et throws
Classe ou interface localele reste du bloc, y compris sa propre déclaration
Variable localele reste du bloc, à partir de son propre initialiseur
Variable du forl'initialisation, la condition, la mise à jour et le corps
Paramètre d'exceptionle bloc du catch
Ressource de tryles ressources suivantes et le bloc try

§6.3.1Portée des variables de motif dans les expressions

Une variable de motif (o instanceof String s) n'a pas une portée « jusqu'à la fin du bloc ». Sa portée est calculée par analyse de flux : elle est en portée là où le motif a forcément réussi. La spec définit, pour chaque expression, deux ensembles :

  • les variables introduites quand elle est vraie ;
  • les variables introduites quand elle est fausse.

Règle

C'est une erreur si une variable de motif serait introduite deux fois par la même expression (a instanceof String s && b instanceof Integer s), ou si elle porte le nom d'une variable locale déjà en portée.

§6.3.2Portée des variables de motif dans les instructions

Certaines instructions propagent des variables de motif vers les instructions qui les suivent dans le bloc (§6.3.2.1). C'est ce qui rend possible le style « garde puis utilisation » :

InstructionVariables introduites pour la suite du bloc
if (e) S (§6.3.2.2)celles introduites quand e est faux, si S ne peut pas se terminer normalement
if (e) S else Tquand e est vrai si T ne termine pas normalement ; quand e est faux si S ne termine pas normalement
while (e) S (§6.3.2.3)celles introduites quand e est faux, si S ne contient aucun break atteignable vers ce while
do S while (e); (§6.3.2.4)idem
for basique (§6.3.2.5)celles introduites quand la condition est fausse, sans break atteignable
switch (§6.3.2.6), étiquetée (§6.3.2.7)aucune

Dans le corps d'une boucle, les variables introduites quand la condition est vraie sont en portée ; dans la mise à jour d'un for, aussi.

§6.3.3Portée des variables de motif dans les étiquettes case

Une variable déclarée par un motif de case est en portée dans sa garde when, puis dans l'expression, le bloc ou l'instruction throw de la règle (->), ou dans les instructions du groupe (:).

§6.4Masquage et obscurcissement

Une variable locale, un paramètre (de méthode, constructeur, lambda, exception) ou une variable de motif ne peut pas être redéclaré dans sa propre portée, même dans un bloc imbriqué. C'est une erreur de compilation, contrairement à C.

Java
void m(int x) {
    int x = 1;                  // ERREUR : x déjà déclaré (paramètre)
    for (int i = 0; ; ) { int i = 2; }       // ERREUR
    Runnable r = () -> { int x = 3; };      // ERREUR : une lambda ne crée pas de nouvelle portée pour les noms
    Function<Integer,Integer> f = x -> x;   // ERREUR : paramètre de lambda nommé x
    Runnable ok = new Runnable() {
        public void run() { int x = 4; }    // OK : une classe (même anonyme) ouvre une nouvelle portée
    };
}

§6.4.1Masquage (shadowing)

Une déclaration d d'un nom n masque les autres déclarations de même nom et de même sorte (variable, type, méthode) en portée là où d est en portée. Le nom simple n désigne alors d. Cas typiques :

  • un paramètre ou une locale masque un champ : this.x = x; dans un constructeur ;
  • un champ d'une classe imbriquée masque celui de la classe englobante : Externe.this.x ;
  • un type déclaré masque un type importé à la demande ou de même nom ailleurs ;
  • une méthode déclarée masque les méthodes de même nom des classes englobantes, quel que soit le nombre de paramètres.
Java
class Externe {
    int x = 1;
    void f(String s) { }
    class Interne {
        int x = 2;
        void f() { }
        void test() {
            int x = 3;
            System.out.println(x);              // 3
            System.out.println(this.x);         // 2
            System.out.println(Externe.this.x); // 1
            f("a");      // ERREUR : f() de Interne masque TOUTES les f de Externe
            Externe.this.f("a");   // OK
        }
    }
}

§6.4.2Obscurcissement (obscuring)

Dans un contexte où un nom simple pourrait désigner une variable, un type ou un paquetage, la spec donne la priorité dans cet ordre : variable, puis type, puis paquetage. Un type ou un paquetage peut ainsi être obscurci et devenir inaccessible par son nom simple.

Java
class Piege {
    static String System = "?";   // un champ nommé System
    void m() {
        System.out.println("x");     // ERREUR : System est la variable ; String n'a pas de champ out
        java.lang.System.out.println("x");   // OK : nom qualifié
    }
}

Les conventions de nommage (§6.1) évitent ce problème : variables en minuscules, types en majuscule initiale, paquetages en minuscules mais avec un domaine qu'aucune variable ne porte.

§6.5Déterminer le sens d'un nom

Le compilateur procède en deux temps : d'abord il classe syntaxiquement chaque nom d'après sa position (§6.5.1), ensuite il cherche la déclaration correspondante selon la catégorie (§6.5.3 à §6.5.7).

§6.5.2Reclassification des noms ambigus

Règle · nom ambigu simple

S'il désigne une variable en portée (locale, paramètre, champ), c'est un ExpressionName. Sinon, s'il désigne une classe ou interface en portée, c'est un TypeName. Sinon, c'est un PackageName. Pour un nom qualifié Q.Id, on reclasse d'abord Q, puis Id selon ce que Q est devenu.

§6.5.3Sens des noms de modules et de paquetages

Un nom de module désigne un module ; deux modules de même nom ne peuvent pas coexister dans la même configuration (§7.7.6). Un nom de paquetage simple désigne le paquetage de premier niveau de ce nom (§6.5.3.1) ; un nom qualifié Q.Id désigne le sous-paquetage Id de Q (§6.5.3.2). Les paquetages ne sont pas hiérarchiques au sens de l'accès : java.util n'a aucun privilège sur java.util.concurrent.

§6.5.4Sens des PackageOrTypeName

Simple (§6.5.4.1) : si un type de ce nom est en portée, c'est un TypeName, sinon un PackageName. Qualifié Q.Id (§6.5.4.2) : si Q est un type ou un paquetage qui contient un membre type Id, c'est un TypeName, sinon un PackageName.

§6.5.5Sens des noms de types

Simple (§6.5.5.1) : il doit y avoir exactement une classe, une interface ou un paramètre de type visible de ce nom, sinon erreur (ambiguïté entre deux imports à la demande, par exemple). Qualifié Q.Id (§6.5.5.2) : Id doit être un membre type accessible du paquetage ou du type Q.

Java
import java.util.*;
import java.awt.*;
List l;              // ERREUR : java.util.List et java.awt.List sont tous deux importés à la demande
java.util.List l2;   // OK : nom qualifié

§6.5.6Sens des noms d'expressions

Un nom d'expression simple (§6.5.6.1) désigne la variable locale, le paramètre ou le champ en portée. Si c'est un champ d'instance, le nom doit apparaître dans un contexte non statique, sinon erreur. Si c'est une variable locale d'une méthode englobante utilisée dans une classe interne ou une lambda, elle doit être final ou effectivement final (§4.12.4).

Un nom d'expression qualifié Q.Id (§6.5.6.2) : si Q est un type, Id doit en être un champ statique ; si Q est une expression, Id est un champ du type de Q (un champ d'instance ou statique, ce dernier étant déconseillé).

Java
class C {
    int inst; static int stat;
    static void s() {
        inst = 1;     // ERREUR : champ d'instance dans un contexte statique
        stat = 1;     // OK
    }
}
C c = null;
c.stat = 5;           // compile (style déconseillé) et ne lève pas de NPE : seul le type de c compte

§6.5.7Sens des noms de méthodes

Un nom de méthode simple (§6.5.7.1) apparaît dans un appel non qualifié m(…). La recherche de la méthode, la résolution de surcharge et la vérification d'accès sont décrites au §15.12. La seule règle de ce chapitre : il faut qu'au moins une méthode de ce nom soit en portée, en tenant compte du masquage décrit au §6.4.1.

§6.6Contrôle d'accès

Le contrôle d'accès est une vérification à la compilation (et à l'exécution par la JVM) qui limite l'usage d'un nom qualifié, d'un accès de champ, d'un appel de méthode ou d'une création d'instance. Accès et portée sont indépendants : un nom peut être en portée sans être accessible, et un membre accessible peut être hors de portée (on le désigne alors par un nom qualifié).

§6.6.1Déterminer l'accessibilité

Un paquetage est accessible s'il est uniquement visible (§7.4.3). Une classe ou interface de plus haut niveau public est accessible partout où son module la rend accessible : dans son module, et dans les modules qui lisent ce module si le paquetage est exporté. Une classe non publique n'est accessible que dans son paquetage. Pour les membres :

§6.6.2Les détails de l'accès protected

§6.6.2.1Accès à un membre protected

En dehors de son paquetage, un membre protected d'une classe C n'est accessible que dans le corps d'une sous-classe S de C, et seulement si l'accès se fait à travers une expression dont le type est S ou un sous-type de S. L'idée : une sous-classe a le droit de manipuler la partie protégée de ses propres objets, pas celle de n'importe quel objet de type C.

Java · deux paquetages
package a;
public class Animal { protected int age; protected void vieillir() { age++; } }

package b;
public class Chien extends a.Animal {
    void test(a.Animal autre, Chien chien, Caniche caniche) {
        age = 3;              // OK : this, de type Chien
        chien.age = 3;        // OK : expression de type Chien
        caniche.vieillir();   // OK : Caniche est un sous-type de Chien
        autre.age = 3;        // ERREUR : expression de type Animal
        ((Chien) autre).age = 3;  // OK après cast
    }
}
class Caniche extends Chien { }

§6.6.2.2Accès à un constructeur protected

En dehors de son paquetage, un constructeur protected ne peut être appelé que par super(…) dans le constructeur d'une sous-classe, ou par la création d'une classe anonyme new C(…) { … }. Une simple instanciation new C(…) est interdite.

Java
package a; public class Base { protected Base() {} }

package b;
class Sous extends a.Base {
    Sous() { super(); }            // OK
    void f() {
        new a.Base();              // ERREUR
        new a.Base() { };          // OK : classe anonyme sous-classe de Base
    }
}
Note non normative

L'accès private est défini au niveau de la classe de plus haut niveau qui englobe la déclaration : deux classes imbriquées dans la même classe externe accèdent librement à leurs membres privés mutuels. Depuis Java 11, la JVM le permet directement (« nestmates ») sans méthodes d'accès synthétiques.

Un même type membre peut avoir plusieurs noms pleinement qualifiés quand il est hérité : si O2 extends O1 et que O1 déclare I, alors p.O1.I et p.O2.I le désignent tous deux. Le nom canonique est l'unique nom pleinement qualifié qui passe par la classe déclarante : p.O1.I.

Java · trois sortes de noms
Class<?> c = java.util.Map.Entry.class;
c.getName();            // "java.util.Map$Entry"   : nom binaire (§13.1), utilisé par la JVM
c.getCanonicalName();   // "java.util.Map.Entry"   : nom canonique
c.getSimpleName();      // "Entry"

new Object(){}.getClass().getCanonicalName();   // null : une classe anonyme n'a pas de nom canonique
int[][].class.getName();                         // "[[I" : descripteur de la JVM
