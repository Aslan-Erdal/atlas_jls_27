Chapitre 10 · Java SE 27 Edition

Tableaux

En Java, un tableau est un objet : créé dynamiquement, désigné par une référence, de longueur fixe, avec des accès toujours vérifiés. Ce chapitre décrit leurs types, leur création, leur accès, leur covariance et ses dangers, et ce qui les distingue des chaînes.

Source : JLS SE 27, chapitre 10 Sections : 10.1 à 10.9

§10Ce qu'est un tableau

Un tableau contient un nombre fixe de variables sans nom, ses composants, toutes du même type, le type de composant. Si ce type est T, le tableau est de type T[]. Le nombre de composants, sa longueur, est fixé à la création et ne change jamais ; il peut être nul. Les composants sont indexés de 0 à length − 1.

Le type de composant peut être lui-même un tableau : Java n'a pas de tableaux multidimensionnels, mais des tableaux de tableaux. Le type d'élément est le type obtenu en retirant tous les crochets : pour int[][], le type de composant est int[] et le type d'élément int.

§10.1Types tableau

Un type tableau s'écrit comme un type suivi de paires de crochets. Sa longueur ne fait pas partie du type : int[] désigne tous les tableaux d'entiers, quelle que soit leur taille. Les supertypes d'un tableau sont décrits au §4.10.3 : Object, Cloneable, java.io.Serializable, et, pour un tableau de références, les tableaux de supertypes.

§10.2Variables de type tableau

Déclarer une variable de type tableau ne crée pas de tableau : la variable contient null (champ) ou n'est pas encore assignée (locale). Les crochets peuvent se placer après le type, après le nom, ou les deux (héritage du C) :

Java
int[] a;          // forme recommandée
int b[];          // forme C : permise, déconseillée
int[] c, d[];     // c : int[] ; d : int[][]  (piège de lecture !)
int[] f()[] { }   // méthode qui renvoie int[][] : légal mais illisible
var e = new int[3];   // var ne peut pas avoir de crochets : var x[] est une erreur

§10.3Création de tableaux

Un tableau est créé par une expression de création (new int[5], §15.10.1) ou par un initialiseur ({1, 2, 3}, §10.6). La longueur est une expression de type int (après promotion unaire) : un long est refusé, une valeur négative lève NegativeArraySizeException.

Java
int[] t = new int[5];          // cinq 0
String[] s = new String[2];    // deux null
int[][] m = new int[3][4];     // 3 tableaux de 4 int
int[][] j = new int[3][];      // 3 null : les lignes restent à créer
int[] z = new int[0];          // tableau vide, distinct de null
new int[-1];                   // NegativeArraySizeException
new int[3L];                   // ERREUR : long n'est pas promu en int
new ArrayList<String>[10];     // ERREUR : création de tableau générique (§4.7)

Suivez ce qui se passe en mémoire :

§10.4Accès aux tableaux

Un composant se désigne par a[i]. L'index subit une promotion numérique unaire : byte, short, char deviennent int ; un long est une erreur de compilation.

Règles · toujours vérifié

Chaque accès est contrôlé à l'exécution : un index hors de 0 … length−1 lève ArrayIndexOutOfBoundsException, une référence null lève NullPointerException. L'expression du tableau est évaluée avant l'index, et l'index est évalué même si la référence est null (§15.10.4).

Java
int[] a = {10, 20, 30};
a['\u0001'];       // 20 : char promu en int
a[3];              // ArrayIndexOutOfBoundsException: Index 3 out of bounds for length 3
int[] n = null;
n[idx()];          // idx() est appelé, PUIS NullPointerException

§10.5ArrayStoreException

Les tableaux de références sont covariants : un String[] est un Object[]. Pour que cela reste sûr, chaque écriture dans un tableau de références vérifie, à l'exécution, que la valeur est compatible avec le type de composant réel du tableau.

Java
Object[] objets = new String[2];   // permis : String[] <: Object[]
objets[0] = "ok";                  // vérifié : String, OK
objets[1] = 42;                    // ArrayStoreException: java.lang.Integer

List<Object> liste = new ArrayList<String>();   // ERREUR de compilation : génériques invariants

Cette vérification a un coût à chaque écriture, et ne découvre l'erreur qu'à l'exécution. Les génériques ont été conçus invariants précisément pour l'éviter : c'est pour ça qu'on ne mélange pas bien tableaux et génériques.

§10.6Initialiseurs de tableaux

Un initialiseur est une liste entre accolades d'expressions (ou d'initialiseurs imbriqués). Il crée un tableau de la longueur de la liste et affecte les composants de gauche à droite. Une virgule finale est permise, ce qui facilite la génération de code et les diffs.

Java
int[] premiers = {2, 3, 5, 7, 11,};          // virgule finale permise
String[][] grille = {{"a", "b"}, {"c"}};       // irrégulier
int[] t;
t = {1, 2};                                   // ERREUR : forme courte seulement dans une déclaration
t = new int[]{1, 2};                          // OK
f(new String[]{"x", "y"});                    // en argument : forme avec new
var v = {1, 2};                               // ERREUR : var ne fournit pas de type cible

§10.7Membres d'un tableau

  • le champ public final int length ;
  • la méthode public T[] clone(), qui redéfinit Object.clone : publique, sans exception vérifiée, et qui renvoie le même type de tableau (pas besoin de cast) ;
  • tous les autres membres hérités de Object.
Piège

equals et hashCode d'un tableau sont ceux de Object : ils comparent l'identité. Pour comparer des contenus : Arrays.equals, Arrays.deepEquals (imbriqués), Arrays.hashCode. Pour afficher : Arrays.toString et Arrays.deepToString.

Java
int[] a = {1, 2}, b = {1, 2};
a.equals(b);               // false
Arrays.equals(a, b);       // true
Set.of(a).contains(b);     // false : un tableau comme clé de HashSet est presque toujours un bug
System.out.println(a);     // [I@1b6d3586
Arrays.toString(a);        // "[1, 2]"

§10.8Objets Class des tableaux

Chaque type tableau a un objet Class unique, partagé par tous les tableaux de ce type, quelle que soit leur longueur. Son nom suit la notation des descripteurs de la JVM :

ExpressiongetName()getComponentType()
int[].class[Iint
long[][].class[[Jlong[]
String[].class[Ljava.lang.String;String
boolean[].class[Zboolean

Les codes : B byte, C char, D double, F float, I int, J long, S short, Z boolean, L…; classe. new int[3].getClass() == new int[100].getClass() vaut true.

§10.9Un tableau de char n'est pas une String

Contrairement au C, une String n'est pas un char[], et aucun des deux ne se termine par '\u0000'. Une String est immuable ; un char[] se modifie. Les surcharges de l'API les traitent différemment :

Java
char[] c = {'J', 'a', 'v', 'a'};
System.out.println(c);           // Java     : surcharge println(char[])
System.out.println("" + c);      // [C@4554617c : concaténation → toString de Object
String s = new String(c);        // copie : modifier c ensuite ne change pas s
String t = String.valueOf(c);    // idem
char[] d = s.toCharArray();      // nouvelle copie
Note non normative

Pour les secrets (mots de passe), l'API préfère parfois char[] (Console.readPassword) : on peut l'effacer après usage, alors qu'une String reste en mémoire jusqu'au passage du ramasse-miettes.
