Streams et programmation fonctionnelle

Les lambdas (§15.27) et les références de méthodes (§15.13) prennent tout leur sens avec l'API Stream : des pipelines déclaratifs, paresseux, éventuellement parallèles, pour transformer des données. Cette section couvre leur fonctionnement réel, les collecteurs, les gatherers de Java 24, Optional et les pièges.

Référence : API Java SE 27, java.util.stream Liens avec la JLS : §9.8, §15.13, §15.27, ch. 18

21.1Composer des fonctions

Les interfaces de java.util.function (§9.8) ont des méthodes default qui permettent de composer sans écrire de nouvelle lambda :

Java
Function<String, String> nettoyer = String::strip;
Function<String, Integer> longueur = nettoyer.andThen(String::length);   // strip puis length
Function<Integer, Integer> doubler = x -> x * 2;
doubler.compose(longueur).apply("  abc ");   // 6 : longueur d'abord, puis doubler

Predicate<String> vide = String::isBlank;
Predicate<String> utile = vide.negate().and(s -> s.length() < 80);
liste.stream().filter(Predicate.not(String::isBlank));   // Predicate.not (Java 11)

UnaryOperator<String> id = UnaryOperator.identity();
BinaryOperator<Integer> max = BinaryOperator.maxBy(Comparator.naturalOrder());

21.2Anatomie d'un stream

Un stream n'est pas une structure de données : c'est une description de calcul sur une suite d'éléments. Il comporte une source, zéro ou plusieurs opérations intermédiaires (qui renvoient un stream) et une opération terminale (qui produit un résultat ou un effet).

Propriétés fondamentales
  • Paresse : les opérations intermédiaires ne font rien tant qu'aucune opération terminale n'est appelée.
  • Traitement élément par élément : chaque élément traverse toute la chaîne avant le suivant, sauf aux opérations avec état (sorted, distinct), qui doivent tout voir.
  • Court-circuit : limit, findFirst, anyMatch… arrêtent dès que possible, ce qui permet de traiter des streams infinis.
  • Usage unique : réutiliser un stream déjà consommé lève IllegalStateException.
  • Non-interférence : la source ne doit pas être modifiée pendant le pipeline ; les lambdas devraient être sans effet de bord.

21.5Opérations terminales

Java
List<String> l = s.toList();                       // immuable, accepte null (Java 16)
long n = s.count();
Optional<String> premier = s.findFirst();

IntSummaryStatistics st = ints.summaryStatistics(); // min, max, moyenne, somme, nombre

String[] t = s.toArray(String[]::new);
s.forEach(System.out::println);                    // ordre non garanti en parallèle : forEachOrdered
reduce : identité et associativité

L'élément identité doit vraiment être neutre (0 pour la somme, 1 pour le produit), et l'opération associative : sinon le résultat change en parallèle. Pour accumuler dans un conteneur mutable, utilisez collect, pas reduce.

21.7Gatherers (Java 24)

Les collecteurs personnalisent l'opération terminale ; les gatherers (JEP 485, finalisé en Java 24) personnalisent les opérations intermédiaires. stream.gather(g) applique un Gatherer, qui peut garder un état, émettre plusieurs éléments, s'arrêter tôt.

Java 24+
Stream.of(1, 2, 3, 4, 5, 6, 7)
      .gather(Gatherers.windowFixed(3))        // [[1, 2, 3], [4, 5, 6], [7]]
      .toList();
Stream.of(1, 2, 3, 4)
      .gather(Gatherers.windowSliding(2))      // [[1, 2], [2, 3], [3, 4]]
      .toList();
Stream.of(1, 2, 3, 4)
      .gather(Gatherers.scan(() -> 0, Integer::sum))   // sommes cumulées : 1, 3, 6, 10
      .toList();
urls.stream()
    .gather(Gatherers.mapConcurrent(16, Http::telecharger))  // jusqu'à 16 appels concurrents (threads virtuels), ordre conservé
    .toList();

// gatherer personnalisé : ne garder que les éléments différents du précédent
Gatherer<String, ?, String> sansRepetition = Gatherer.ofSequential(
    () -> new String[1],
    (etat, elt, aval) -> {
        if (!elt.equals(etat[0])) { etat[0] = elt; return aval.push(elt); }
        return true;
    });

21.8Streams primitifs

IntStream, LongStream et DoubleStream évitent le boxing (§5.1.7) : sur de gros volumes, la différence de performance est importante. Passez de l'un à l'autre avec mapToInt, mapToObj, boxed.

Java
int somme = ventes.stream().mapToInt(v -> (int) v.montant()).sum();   // pas de Integer intermédiaires
OptionalDouble moyenne = IntStream.range(0, 0).average();             // vide : OptionalDouble.empty()
Stream<Integer> lent = Stream.iterate(0, i -> i + 1).limit(1_000_000);   // un Integer par élément

21.9Optional

Optional<T> représente un résultat qui peut être absent. Il est conçu comme type de retour, pour forcer l'appelant à traiter l'absence.

Java
Optional<Client> c = repo.trouver(id);
String nom = c.map(Client::nom).orElse("inconnu");
Client cl = c.orElseThrow(() -> new IntrouvableException(id));
c.ifPresentOrElse(this::afficher, () -> log("absent"));
Optional<Adresse> a = c.flatMap(Client::adresse);      // si adresse() renvoie déjà un Optional
c.filter(Client::actif).or(() -> repo.trouverArchive(id));

c.orElse(creerParDefaut());        // piège : creerParDefaut() est TOUJOURS appelé
c.orElseGet(this::creerParDefaut); // appelé seulement si vide
c.get();                           // NoSuchElementException si vide : préférer orElseThrow()
Bonne pratique

N'utilisez pas Optional comme type de champ, de paramètre ou d'élément de collection, et ne renvoyez jamais null à la place d'un Optional. Pour les primitifs : OptionalInt, OptionalLong, OptionalDouble.

21.10Streams parallèles

parallelStream() ou .parallel() découpe la source (via son Spliterator) et traite les morceaux sur le ForkJoinPool commun, dont la taille par défaut est le nombre de cœurs moins un.

FavorableDéfavorable
beaucoup d'éléments (au moins des dizaines de milliers)peu d'éléments : le découpage coûte plus qu'il ne rapporte
calcul coûteux par élément, sans attenteentrées-sorties bloquantes (utilisez des threads virtuels, section 22)
source bien découpable : ArrayList, tableaux, IntStream.rangeLinkedList, Stream.iterate, Files.lines
opérations sans état ni ordre : map, filter, sumlimit, findFirst, sorted, forEachOrdered sur une source ordonnée
Effets de bord en parallèle
Java
List<Integer> resultats = new ArrayList<>();
IntStream.range(0, 10_000).parallel().forEach(resultats::add);   // course de données : taille fausse, exceptions
List<Integer> ok = IntStream.range(0, 10_000).parallel().boxed().toList();   // correct

int[] compteur = {0};
stream.forEach(x -> compteur[0]++);   // contourne « effectivement final », mais faux en parallèle : utilisez count()

21.11Pièges fréquents

peek n'est pas garantiDepuis Java 9, count() peut calculer la taille sans parcourir les éléments si la source la connaît : un peek ou un map en amont peut alors ne jamais s'exécuter.
Stream infini sans arrêtStream.iterate(1, x -> x + 1).filter(x -> x < 10).toList() ne termine jamais : filter ne sait pas qu'il n'y aura plus d'éléments utiles. Utilisez takeWhile.
RessourcesFiles.lines et Files.list ouvrent des fichiers : un stream implémente AutoCloseable, utilisez try-with-resources.
Exceptions vérifiéesUne lambda passée à map ne peut pas lever d'exception vérifiée (§11.2.1). Enveloppez-la (UncheckedIOException) ou traitez-la dans la lambda.
Tout n'est pas un streamUne boucle simple reste plus lisible pour un traitement à effets de bord, avec break ou plusieurs accumulateurs. Les streams brillent pour les transformations déclaratives.
sorted puis findFirstTrier pour prendre le minimum coûte O(n log n) ; min(cmp) est en O(n).
