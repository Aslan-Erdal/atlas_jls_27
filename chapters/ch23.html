Entrées-sorties et java.time

Deux API que tout programme utilise et que la JLS ne décrit pas : lire et écrire des données (fichiers, texte, réseau) et manipuler correctement les dates, les heures et les fuseaux horaires.

23.2Octets, caractères et encodages

Un fichier contient des octets. Un texte Java est une suite de caractères UTF-16 (§3.1). Passer de l'un à l'autre exige un encodage (Charset). Si l'écrivain et le lecteur n'utilisent pas le même, le texte est corrompu (« mojibake »). Depuis Java 18 (JEP 400), l'encodage par défaut est UTF-8 sur toutes les plateformes ; nommez-le quand même explicitement.

Les classes de java.io se composent selon le patron décorateur : chaque couche enveloppe la précédente et ajoute une capacité.

23.3Fichiers avec Path et Files

Path désigne un chemin (qui n'existe pas forcément) ; la classe utilitaire Files agit sur le système de fichiers. Les anciennes java.io.File et FileReader restent disponibles, mais Files signale mieux les erreurs (exceptions précises au lieu d'un false).

Fermer les ressources

Tout ce qui implémente AutoCloseable (flux, lecteurs, canaux, Files.lines, connexions) se déclare dans un try-with-resources (§14.20.3). Les ressources sont fermées dans l'ordre inverse, même en cas d'exception ; une exception de fermeture est ajoutée comme « supprimée » (getSuppressed()) à l'exception principale.

Dans une lambda, une IOException vérifiée ne peut pas sortir (ch. 11) : enveloppez-la dans une UncheckedIOException, que Files.lines lève d'ailleurs elle-même en cas d'erreur de lecture pendant le parcours.

23.4Console : IO, System.in et System.out

Depuis Java 25 (JEP 512), la classe java.lang.IO offre des méthodes statiques simples, importées automatiquement dans les fichiers source compacts :

Java 25+ · fichier source compact
void main() {
    String nom = IO.readln("Votre nom : ");
    IO.println("Bonjour " + nom);
}

Ailleurs, System.out est un PrintStream et System.in un InputStream brut : enveloppez-le dans un BufferedReader ou un Scanner. System.console() permet de lire un mot de passe sans écho (readPassword).

23.5Sérialisation

23.6HttpClient

Java 11+
try (HttpClient client = HttpClient.newBuilder()          // AutoCloseable depuis Java 21
        .connectTimeout(Duration.ofSeconds(5))
        .followRedirects(HttpClient.Redirect.NORMAL)
        .build()) {

    HttpRequest req = HttpRequest.newBuilder(URI.create("https://api.exemple.fr/clients/42"))
        .header("Accept", "application/json")
        .timeout(Duration.ofSeconds(10))
        .GET().build();

    HttpResponse<String> rep = client.send(req, HttpResponse.BodyHandlers.ofString());   // synchrone
    if (rep.statusCode() == 200) traiter(rep.body());

    client.sendAsync(req, HttpResponse.BodyHandlers.ofString())                         // asynchrone
          .thenApply(HttpResponse::body)
          .thenAccept(System.out::println);
}

Avec des threads virtuels (section 22), l'appel synchrone send est souvent le plus lisible. HTTP/3 est disponible depuis Java 26 (JEP 517) via HttpClient.Version.HTTP_3.

23.7Canaux, tampons et mémoire hors tas

Pour les cas exigeants, NIO travaille avec des ByteBuffer (position, limite, capacité) et des FileChannel. FileChannel.map projette un fichier en mémoire ; transferTo copie de canal à canal sans passer par l'espace utilisateur quand le système le permet. Depuis Java 22, l'API Foreign Function & Memory (Arena, MemorySegment) gère de la mémoire hors tas de façon sûre (accès bornés, libération déterministe) et dépasse la limite de 2 Gio des ByteBuffer.

Java 22+
try (Arena arena = Arena.ofConfined();
     FileChannel ch = FileChannel.open(f, StandardOpenOption.READ)) {
    MemorySegment seg = ch.map(FileChannel.MapMode.READ_ONLY, 0, ch.size(), arena);
    byte premier = seg.get(ValueLayout.JAVA_BYTE, 0);
}   // le segment est libéré à la fermeture de l'arène

23.8java.time : choisir le bon type

L'API java.time (Java 8, JSR 310) remplace Date et Calendar. Tous ses types sont immuables et sûrs entre threads. La difficulté est de choisir le type qui correspond à ce qu'on représente :

Je représente…Type
un horodatage technique (journal, base, événement)Instant
une date d'anniversaire, une échéance « le 15 »LocalDate
l'heure d'ouverture d'un magasinLocalTime
un rendez-vous dans une villeZonedDateTime (ou LocalDateTime + ZoneId stockés séparément)
un échange avec un système externe (JSON, SQL)OffsetDateTime ou Instant
une durée mesurée (« 90 secondes »)Duration
une durée calendaire (« 1 mois »)Period
« maintenant », de façon testableun Clock injecté : Instant.now(clock)

23.9Fuseaux horaires et heure d'été

Un ZoneId comme Europe/Paris porte des règles : le décalage change deux fois par an. Il existe donc des heures locales qui n'existent pas (le « trou » du printemps) et d'autres qui existent deux fois (le « chevauchement » de l'automne). Java les résout de manière déterministe :

  • Trou : l'heure est décalée vers l'avant de la durée du trou (02:30 devient 03:30) ;
  • Chevauchement : le décalage antérieur à la transition est retenu ; withLaterOffsetAtOverlap() choisit l'autre.
