Chapitre 3 · Java SE 27 Edition

Structure lexicale

Avant toute analyse, le compilateur lit des caractères et les découpe en jetons. Ce chapitre fixe les règles de ce découpage : Unicode, échappements, commentaires, identifiants, mots-clés et toutes les formes de littéraux.

Source : JLS SE 27, chapitre 3 Sections : 3.1 à 3.12 Unicode : version 17.0

§3.1Unicode

Un programme Java est écrit en Unicode. La JLS 27 s'aligne sur Unicode 17.0. Les caractères d'origine (le « plan multilingue de base ») tiennent sur 16 bits, mais Unicode va aujourd'hui jusqu'à U+10FFFF. Java représente le texte en UTF-16 :

  • un point de code (code point) est un caractère Unicode abstrait, de U+0000 à U+10FFFF ;
  • une unité de code UTF-16 est une valeur de 16 bits, c'est ce que contient un char ;
  • les caractères au-delà de U+FFFF (dits supplémentaires) occupent deux unités de code : une paire de substitution (surrogate pair), U+D800–DBFF puis U+DC00–DFFF.
Java
String s = "é😀";
s.length();                      // 3 : 'é' = 1 unité, '😀' (U+1F600) = 2 unités
s.codePointCount(0, s.length()); // 2 points de code
char c = s.charAt(1);            // '\uD83D' : une moitié de paire, pas un caractère complet
char x = '😀';                   // ERREUR : un littéral char ne contient qu'une unité de code
Règle

Sauf mention contraire (commentaires, identifiants, contenu des littéraux), un programme n'utilise que des caractères ASCII pour ses jetons. Mais n'importe quel caractère Unicode peut apparaître sous forme brute ou via un échappement \uXXXX (§3.3).

§3.2Les traductions lexicales

Le flux brut de caractères passe par trois traductions successives, toujours dans cet ordre :

  1. Échappements Unicode : chaque \uXXXX est remplacé par le caractère qu'il désigne (§3.3). On peut ainsi écrire n'importe quel caractère avec seulement de l'ASCII.
  2. Fins de ligne : le flux résultant est découpé en lignes en reconnaissant les terminateurs (§3.4).
  3. Éléments d'entrée : les lignes sont découpées en espaces, commentaires et jetons (§3.5). Espaces et commentaires sont ensuite écartés.
Règle · la traduction la plus longue

À chaque étape du découpage, le compilateur prend la plus longue suite de caractères qui forme un élément valide, même si cela rend le programme incorrect ensuite. a--b devient a, --, b (puis erreur de syntaxe), jamais a, -, -b.

Une seule exception : dans un contexte de type (§4.11), les caractères >> et >>> sont réduits à des > successifs. Sans cette règle, List<List<String>> serait une erreur, ce qui était effectivement le cas en C++ avant 2011.

§3.3Échappements Unicode

Un échappement Unicode est une barre oblique inverse, un ou plusieurs u, puis exactement quatre chiffres hexadécimaux : \u0041, \uuu0041 désignent tous deux A. Plusieurs u sont permis pour qu'un outil puisse convertir un fichier en ASCII et revenir en arrière sans ambiguïté.

Règle · quelles barres obliques comptent ?

Une \ ne peut commencer un échappement Unicode que si elle est précédée d'un nombre pair de \ contiguës (zéro compris). Dans \\u0041, la seconde barre est précédée d'une barre : elle n'est pas éligible. Le texte reste \\u0041, que la chaîne interprète ensuite comme \ suivi de u0041.

Un caractère produit par un échappement Unicode ne participe à aucun autre échappement Unicode : \u005cu0041 (\u005c = \) ne devient pas A.

Comme cette traduction a lieu avant tout, elle s'applique partout, y compris dans les commentaires et les chaînes. D'où plusieurs pièges célèbres :

Java
// Chemin : c:\users\moi       ERREUR : \users n'est pas un échappement Unicode valide

// \u000a System.out.println("exécuté !");
//   \u000a devient un saut de ligne : la suite n'est plus dans le commentaire et s'exécute

String q = "\u0022";   // ERREUR : devient """ (délimiteur de text block) suivi de ;
char a = '\u0027';     // ERREUR : devient '''
char n = '\u000a';     // ERREUR : un vrai saut de ligne dans un littéral caractère
char ok = '\n';        // correct : séquence d'échappement (§3.10.7), traitée bien plus tard
À retenir

Échappements Unicode (§3.3) et séquences d'échappement (§3.10.7) n'ont rien à voir : les premiers sont traduits au tout début, partout ; les secondes ne sont interprétées que dans les littéraux caractère, chaîne et text block. Pour un caractère spécial dans une chaîne, utilisez toujours une séquence d'échappement.

§3.4Terminateurs de ligne

Trois formes sont reconnues : LF (\n, Unix), CR (\r, ancien Mac OS) et la paire CR LF (Windows), qui compte pour un seul terminateur. Les lignes servent à deux choses : terminer un commentaire // et numéroter les lignes dans les messages d'erreur. Les terminateurs sont ensuite traités comme des espaces.

Un littéral chaîne ou caractère ne peut pas contenir de terminateur brut ; seul un text block (§3.10.6) le peut.

§3.5Éléments d'entrée et jetons

Le résultat de la troisième traduction est une suite d'éléments d'entrée : espaces blancs, commentaires et jetons. Les jetons sont les seuls qui comptent pour la grammaire syntaxique.

Grammaire lexicale (forme résumée)
Input::
    {InputElement} [Sub]

InputElement::
    WhiteSpace
    Comment
    Token

Token::
    Identifier
    Keyword
    Literal
    Separator
    Operator

Sub::
    the ASCII SUB character, also known as "control-Z"

Le caractère SUB (\u001a, Ctrl-Z) est ignoré s'il est le dernier du fichier : c'est une concession aux anciens systèmes qui marquaient ainsi la fin d'un fichier texte.

Espaces et commentaires séparent des jetons qui, accolés, se fondraient : a - -b est valide, a--b ne l'est pas. Ils ne sont jamais à l'intérieur d'un jeton : - = n'est pas l'opérateur -=.

§3.6Espaces blancs

Les espaces blancs sont : l'espace ASCII SP (\u0020), la tabulation horizontale HT (\u0009), le saut de page FF (\u000c) et les terminateurs de ligne.

Piège

L'espace insécable U+00A0, que certains éditeurs ou copier-coller insèrent, n'est pas un espace blanc Java : le compilateur signale un caractère illégal. Même chose pour les espaces Unicode exotiques (U+2003…).

§3.8Identifiants

Un identifiant est une suite de longueur illimitée de lettres Java et de chiffres Java, commençant par une lettre Java. Il ne peut pas avoir la même orthographe qu'un mot-clé réservé, ni que true, false ou null.

  • Une lettre Java est un caractère pour lequel Character.isJavaIdentifierStart(int) renvoie vrai : lettres de toutes les écritures, _, $, symboles monétaires, ponctuations de liaison.
  • Un chiffre Java satisfait Character.isJavaIdentifierPart(int) sans être une lettre : chiffres de toutes les écritures, marques combinantes, certains caractères de contrôle ignorables.
  • Deux identifiants sont identiques seulement s'ils ont les mêmes points de code après traduction des échappements. Les lettres « qui se ressemblent » restent différentes.
Java
int année = 2026, $prix = 9, _tmp = 1;   // OK
double φ = 1.618;                        // OK : lettre grecque
int r² = 0;             // ERREUR : ² (exposant) n'est pas un chiffre Java
int café = 1;
int caf\u00e9 = 2;      // ERREUR : même identifiant que café (déjà déclaré)
int A = 1, Α = 2;       // OK : A latin (U+0041) et Alpha grec (U+0391) sont deux identifiants
int _ = 3;              // ERREUR : _ est un mot-clé ; il sert de variable sans nom (Java 22)
Note non normative

Le $ est permis mais la spec recommande de le réserver au code généré (classes internes compilées Externe$Interne, outils). Dans du code écrit à la main, il prête à confusion.

§3.10Littéraux

Un littéral est la représentation dans le code d'une valeur d'un type primitif, de String ou du type nul. Il y en a huit sortes : entier, flottant, booléen, caractère, chaîne, text block et null.

§3.10.1Littéraux entiers

BasePréfixeChiffresExemples
Décimaleaucun0–9, ne commence pas par 0 (sauf 0 seul)0, 42, 1_000_000
Hexadécimale0x / 0X0–9, a–f, A–F0xCAFE_BABE, 0x7fff_ffff
Octale00–70777, 0_7
Binaire0b / 0B0–10b1010, 0b1111_0000
Règles

Le type est int, ou long avec le suffixe L (préférez la majuscule, l ressemble à 1). Les _ sont permis entre deux chiffres, jamais en tête, en fin, ni contre le préfixe ou le suffixe.

Un littéral décimal int va jusqu'à 2147483647. 2147483648 n'est permis que comme opérande d'un moins unaire (pour écrire Integer.MIN_VALUE). Même règle pour 9223372036854775808L. Les littéraux hexadécimaux, octaux et binaires peuvent utiliser les 32 (ou 64) bits : 0xFFFF_FFFF vaut -1.

§3.10.2Littéraux flottants

Deux formes : décimale (3.14, .5, 1e10, 6.02e23, 2f) et hexadécimale, où l'exposant binaire p est obligatoire (0x1.8p1 = 1,5 × 2¹ = 3,0). Le type est double par défaut, float avec le suffixe f/F ; le suffixe d/D est permis.

Valeurfloatdouble
Plus grande finie3.4028235e38f1.7976931348623157e308
Plus petite normalisée1.17549435e-38f2.2250738585072014e-308
Plus petite non nulle (sous-normale)1.4e-45f4.9e-324
Règles

La valeur est arrondie au plus proche (IEEE 754, arrondi au pair). C'est une erreur de compilation si un littéral non nul s'arrondit à l'infini (1e309) ou à zéro (1e-400). Il n'existe pas de littéral pour l'infini ou NaN : on utilise Double.POSITIVE_INFINITY, Double.NaN, ou une expression comme 1.0 / 0.

Java
double a = 1e3, b = .5, c = 5., d = 0x1p-3;  // 1000.0, 0.5, 5.0, 0.125
float f = 3.14;     // ERREUR : 3.14 est un double, conversion avec perte refusée (§5.2)
float g = 3.14f;    // correct
double h = 09.5;    // OK : le 0 initial ne signifie pas octal pour un flottant
int i = 09;         // ERREUR : 9 n'est pas un chiffre octal
double j = 1_000.5_5; // OK : _ entre chiffres

§3.10.3Littéraux booléens

Deux valeurs, true et false, de type boolean. Rien d'autre (ni 0, ni 1, ni null) ne s'y convertit.

§3.10.4Littéraux caractères

Un caractère unique, ou une séquence d'échappement, entre apostrophes : 'a', '%', '\t', '\u03a9'. Le type est char : une seule unité de code UTF-16.

  • Un caractère supplémentaire (emoji, idéogrammes rares…) ne tient pas dans un char : utilisez un String ou un point de code int.
  • Apostrophe et barre oblique s'écrivent '\'' et '\\'.
  • Pas de fin de ligne brute à l'intérieur : '\u000a' est donc une erreur (voir §3.3).

§3.10.5Littéraux chaînes

Zéro ou plusieurs caractères entre guillemets, sur une seule ligne. Le type est String. Un littéral long se coupe avec +, que le compilateur fusionne en une seule constante.

Règle · l'internement

Un littéral chaîne désigne toujours la même instance de String, quel que soit l'endroit du programme (même classe, autre classe, autre paquetage). Plus généralement, toute expression constante de type String (§15.29) est internée. Une chaîne calculée à l'exécution est un nouvel objet, sauf si on appelle intern().

Java
String a = "Bonjour";
String b = "Bon" + "jour";      // expression constante : calculée à la compilation, internée
final String debut = "Bon";
String c = debut + "jour";      // debut est une variable constante : toujours constant
String fin = "jour";
String d = "Bon" + fin;         // fin n'est pas final : concaténation à l'exécution

a == b;            // true
a == c;            // true
a == d;            // false : objet distinct
a == d.intern();   // true
a.equals(d);       // true : comparez toujours les chaînes avec equals

§3.10.6Text blocks

Un text block est une chaîne sur plusieurs lignes, délimitée par """. Le délimiteur ouvrant doit être suivi (éventuellement après des espaces) d'une fin de ligne : le contenu commence à la ligne suivante.

Le contenu est transformé en trois étapes, dans cet ordre :

  1. les fins de ligne sont normalisées en LF (\n), quel que soit le système ;
  2. les espaces accessoires (incidental whitespace) sont retirés : l'indentation commune à toutes les lignes non vides et à la ligne du délimiteur fermant est supprimée, ainsi que les espaces en fin de chaque ligne ;
  3. les séquences d'échappement sont interprétées.

Cet ordre explique deux échappements propres aux text blocks : \s (un espace, qui survit au retrait des espaces de fin car il n'est interprété qu'après) et \ en fin de ligne, qui supprime la fin de ligne.

Java
String html = """
        <p>
          Bonjour
        </p>
        """;              // "<p>\n  Bonjour\n</p>\n"

String sansFin = """
        une ligne""";     // "une ligne" : pas de \n final

String longue = """
        Une très longue phrase \
        sur une seule ligne.""";   // \ en fin de ligne : pas de saut

String q = """
        Il a dit "oui" et \"""fin\""".""";  // guillemets simples permis ; trois de suite à échapper

String err = """bonjour""";     // ERREUR : le délimiteur ouvrant doit être suivi d'une fin de ligne

Un text block est une expression constante de type String, internée comme un littéral chaîne : "a\nb\n" == """ ↵ a ↵ b ↵ """ vaut true.

§3.10.8Le littéral null

null est le seul littéral du type nul (§4.1). Ce type n'a pas de nom ; on ne peut pas déclarer de variable de ce type. null est assignable à tout type référence, jamais à un type primitif.

§3.11Séparateurs

Douze jetons séparateurs :

(){}[];,....@::

... sert aux paramètres variadiques (§8.4.1), @ aux annotations (§9.7), :: aux références de méthode (§15.13).
