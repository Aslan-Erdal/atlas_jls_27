Section 25 · Plateforme

Outils du JDK

Le JDK n'est pas qu'un compilateur : il fournit de quoi exécuter, explorer, empaqueter, documenter et diagnostiquer une application. Connaître ces outils fait souvent la différence face à un problème en production.

Référence : JDK 27 Tool Specifications Liens : ch. 7 (modules), ch. 12, sections 22 et 24

25.2Décortiquer une ligne de commande

Cliquez sur chaque élément pour savoir ce qu'il fait.

25.3jar et manifeste

Shell
jar --create --file app.jar --main-class fr.exemple.App -C out .   # JAR exécutable
java -jar app.jar
jar --list --file app.jar
jar --describe-module --file app.jar                                  # si c'est un module

Le fichier META-INF/MANIFEST.MF déclare notamment Main-Class, Class-Path, Add-Opens, Enable-Native-Access et Multi-Release: true. Un JAR multi-version contient, sous META-INF/versions/N/, des variantes de classes chargées seulement par une JVM de version N ou plus.

25.4jshell

La boucle interactive de Java (Java 9). Les points-virgules sont facultatifs, les expressions s'affichent, les exceptions vérifiées n'ont pas besoin d'être déclarées.

jshell
$ jshell --enable-preview
jshell> var l = List.of(3, 1, 2)
l ==> [3, 1, 2]
jshell> l.stream().sorted().toList()
$2 ==> [1, 2, 3]
jshell> int carre(int x) { return x * x; }
|  created method carre(int)
jshell> /vars          # aussi : /methods /types /imports /list /edit /save f.jsh /open f.jsh
jshell> /exit

25.5javap : lire le bytecode

javap -c -p Classe.class affiche les instructions de la JVM. C'est le moyen le plus sûr de vérifier ce que le compilateur a réellement produit : méthodes synthétiques, ponts (§15.12.4.5), concaténation de chaînes via invokedynamic, auto-boxing… La JVM est une machine à pile : chaque cadre possède un tableau de variables locales et une pile d'opérandes.

Instruction d'appelUtilisée pour
invokestaticméthodes static
invokevirtualméthodes d'instance de classe (liaison dynamique, §15.12.4.4)
invokeinterfaceméthodes appelées via un type interface
invokespecialconstructeurs, méthodes private, appels super.m()
invokedynamiclambdas, concaténation de chaînes, switch sur motifs, méthodes des records : la liaison est décidée au premier appel par une méthode d'amorçage

25.6Documenter avec javadoc

Java 23+ · commentaires Markdown (JEP 467)
/// Calcule la **somme** de deux entiers.
///
/// - débordement silencieux, comme l'opérateur `+`
/// - voir aussi [Math#addExact(int, int)]
///
/// @param a premier terme
/// @param b second terme
/// @return `a + b`
static int somme(int a, int b) { return a + b; }

La forme classique /** … */ avec HTML reste valable. La balise {@snippet …} (Java 18, JEP 413) insère des exemples de code vérifiables, éventuellement tirés d'un fichier source réel. Générer : javadoc -d doc --module-source-path src --module fr.exemple.app.

25.7Diagnostiquer une JVM en marche

jcmd regroupe la plupart des commandes de diagnostic ; jcmd <pid> help les liste. jps ou jcmd sans argument donnent les identifiants de processus Java.

JDK Flight Recorder

JFR enregistre en continu des événements de la JVM et du JDK (GC, allocations, verrous, E/S, exceptions, compilation) dans un tampon circulaire. On peut l'activer en permanence en production (-XX:StartFlightRecording), puis vider le tampon après un incident (jcmd <pid> JFR.dump). Les fichiers .jfr s'analysent avec jfr ou JDK Mission Control. Java 27 y ajoute le masquage des données sensibles (JEP 536).

25.8Distribuer : jlink et jpackage

Shell
# 1. modules nécessaires
jdeps --print-module-deps --ignore-missing-deps app.jar      # java.base,java.net.http
# 2. runtime minimal
jlink --add-modules java.base,java.net.http --strip-debug --no-header-files \
      --no-man-pages --output runtime
# 3. installeur natif (.msi, .pkg, .deb, .rpm) avec ce runtime
jpackage --name MonApp --input lib --main-jar app.jar --runtime-image runtime --type deb

Avec une image Docker, le runtime produit par jlink remplace un JDK complet et réduit fortement la taille de l'image.

25.9Au-delà du JDK : outils de construction

Les projets réels utilisent Maven ou Gradle, qui appellent javac, gèrent les dépendances et exécutent les tests (JUnit). Les réglages à connaître correspondent directement aux options ci-dessus :

Maven · pom.xml
<properties>
  <maven.compiler.release>27</maven.compiler.release>   <!-- = javac --release 27 -->
</properties>
<!-- preview : <compilerArgs><arg>--enable-preview</arg></compilerArgs> dans maven-compiler-plugin,
     et <argLine>--enable-preview</argLine> dans maven-surefire-plugin pour les tests -->
Gradle · build.gradle.kts
java { toolchain { languageVersion = JavaLanguageVersion.of(27) } }
tasks.withType<JavaCompile> { options.compilerArgs.add("--enable-preview") }
