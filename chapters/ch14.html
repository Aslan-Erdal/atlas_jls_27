Chapitre 14 · Java SE 27 Edition

Blocs, instructions et motifs

La séquence d'exécution d'un programme est contrôlée par des instructions. Ce chapitre les décrit toutes, des blocs aux boucles, du switch moderne au try-with-resources, avant de définir les motifs, qui déclarent et initialisent des variables de façon conditionnelle.

Source : JLS SE 27, chapitre 14 Sections : 14.1 à 14.22, 14.30

§14.1Terminaison normale et abrupte

Chaque instruction a une exécution normale. Mais certaines instructions transfèrent le contrôle ailleurs : on dit qu'elles se terminent abruptement, avec une raison. Toute la sémantique du chapitre repose sur cette notion.

Raison de terminaison abrupteProduite par
break sans étiquettebreak;
break avec étiquette Lbreak L;
yield avec une valeuryield v; dans une switch expression
continue sans / avec étiquettecontinue;, continue L;
return sans / avec valeurreturn;, return v;
throw avec une valeurthrow e;, ou une exception levée par une expression ou la JVM

Si une instruction contient une sous-instruction qui se termine abruptement, elle se termine en général abruptement pour la même raison, sauf mention contraire (une boucle « absorbe » le break qui la vise, un try peut attraper un throw).

§14.2Blocs

Un bloc est une suite d'instructions, de déclarations de classes locales et de variables locales entre accolades. Il s'exécute en exécutant ses éléments dans l'ordre ; si l'un se termine abruptement, le bloc aussi, pour la même raison.

§14.3Déclarations locales de classes et interfaces

Une classe locale est déclarée dans un bloc ; sa portée est le reste du bloc. Depuis Java 16, on peut aussi déclarer des interfaces, enums et records locaux. Ceux-ci sont implicitement static : ils ne peuvent pas capturer les variables locales de la méthode ni l'instance englobante.

Java
List<String> meilleurs(List<Vente> ventes, int seuil) {
    record Total(String vendeur, double montant) { }        // record local : idéal pour un résultat intermédiaire
    return ventes.stream()
        .collect(groupingBy(Vente::vendeur, summingDouble(Vente::montant)))
        .entrySet().stream()
        .map(e -> new Total(e.getKey(), e.getValue()))
        .filter(t -> t.montant() > seuil)                    // seuil capturé par la lambda, pas par le record
        .map(Total::vendeur).toList();
}

Une classe locale ne peut pas être déclarée public, protected, private ni static (explicitement).

§14.4Déclarations de variables locales

Une déclaration de variable locale introduit une ou plusieurs variables, avec un type explicite ou var.

§14.4.1Déclarateurs et types

Règles de var

var déclare une variable dont le type est inféré de son initialiseur. Il faut : un initialiseur ; un seul déclarateur ; pas de crochets ; un initialiseur qui n'est ni null seul, ni un initialiseur de tableau {…}, ni une lambda ou une référence de méthode (qui n'ont pas de type propre). Le type inféré est la projection supérieure du type de l'initialiseur (§4.10.5).

Java
var liste = new ArrayList<String>();  // ArrayList<String>, pas List<String>
var x;                                 // ERREUR : pas d'initialiseur
var n = null;                          // ERREUR : le type nul n'est pas dénotable
var t = {1, 2};                        // ERREUR
var f = () -> 1;                       // ERREUR : une lambda a besoin d'un type cible
var a = 1, b = 2;                      // ERREUR : un seul déclarateur
var obj = new Object() { int compteur; };   // OK : type d'une classe anonyme, non dénotable
obj.compteur++;                        // OK : var permet d'accéder aux membres de la classe anonyme
for (var e : map.entrySet()) { }       // OK
try (var in = Files.newInputStream(p)) { }  // OK
(var s1, var s2) -> s1 + s2            // OK : var dans les paramètres de lambda (pour les annoter)

§14.4.2Instructions de déclaration

Chaque déclarateur est exécuté dans l'ordre, de gauche à droite. Un déclarateur avec initialiseur affecte la valeur ; sans initialiseur, la variable reste non assignée (ch. 16).

§14.5Instructions

La grammaire distingue Statement et StatementNoShortIf pour résoudre le « else pendant » : un else se rattache toujours au if le plus proche qui n'a pas encore de else.

Java
if (a)
    if (b) f();
else            // trompeur : ce else appartient à if (b), pas à if (a)
    g();

§14.6L'instruction vide

; ne fait rien. Attention à if (x); f(); ou while (cond); : le ; est le corps, et f() s'exécute toujours.

§14.7Instructions étiquetées

Toute instruction peut être précédée d'une étiquette L:. Les étiquettes ont leur propre espace de noms : une étiquette peut porter le nom d'une variable. On ne peut pas réutiliser une étiquette déjà en vigueur dans une instruction englobante.

§14.8Instructions-expressions

Seules certaines expressions peuvent servir d'instruction : affectation, ++/-- (préfixe ou suffixe), appel de méthode, création d'instance. a + b; ou x == 1; sont des erreurs, ce qui attrape des fautes de frappe.

§14.9L'instruction if

La condition doit être de type boolean ou Boolean. if-then (§14.9.1) exécute son instruction si la condition est vraie ; if-then-else (§14.9.2) choisit l'une des deux. Une condition Boolean nulle lève NullPointerException.

§14.10L'instruction assert

assert condition; ou assert condition : message;. Les assertions sont désactivées par défaut ; on les active avec java -ea (ou par classe, paquetage). Si activées et la condition fausse, une AssertionError est levée avec le message.

Piège

Ne mettez jamais d'effet de bord dans une assertion (assert liste.remove(x);) : en production, sans -ea, il disparaît. N'utilisez pas assert pour valider les arguments d'une méthode publique : utilisez Objects.requireNonNull ou une exception explicite.

§14.11L'instruction switch

Le switch transfère le contrôle selon la valeur d'une expression, le sélecteur. Depuis Java 14 et 21, il a considérablement évolué : flèches, motifs, gardes, null, exhaustivité.

§14.11.1Blocs switch

Un bloc switch contient soit des règles (case … ->), soit des groupes d'instructions étiquetés (case …:), jamais un mélange. Une étiquette case contient des constantes, des noms d'enum (qualifiés ou non), un ou plusieurs motifs avec garde when facultative, null, ou default.

Groupes case X:Règles case X ->
Chute (fall-through)oui, jusqu'au prochain breaknon : seule la règle choisie s'exécute
Corpssuite d'instructionsune expression, un bloc ou un throw
Plusieurs valeurscase 1, 2: ou étiquettes empiléescase 1, 2 ->
Portée des variablestout le bloc switch (piège)la règle seulement

Comparez l'exécution des deux formes pour chaque valeur :

§14.11.1.1Blocs switch exhaustifs

Un bloc switch est exhaustif si ses étiquettes couvrent toutes les valeurs possibles du sélecteur : un default, un motif inconditionnel, toutes les constantes d'un enum, tous les sous-types autorisés d'un type scellé (récursivement), ou toutes les combinaisons des composants d'un record.

Règle · quand l'exhaustivité est exigée

Toujours pour une switch expression (§15.28). Pour une switch instruction, seulement si elle est « améliorée » : elle utilise un motif ou case null, ou son sélecteur n'est pas d'un type historique (char, byte, short, int, leurs enveloppes, String, enum). Un switch historique sur un int peut rester partiel.

Construisez un switch sur une hiérarchie scellée et observez ce que le compilateur en dit :

§14.11.1.2Quelle étiquette s'applique à l'exécution ?

  1. Si le sélecteur vaut null : la règle case null s'applique si elle existe ; sinon NullPointerException. default n'attrape pas null, sauf écrit case null, default.
  2. Sinon, les étiquettes sont essayées dans l'ordre : une constante égale, ou un motif qui correspond et dont la garde when est vraie.
  3. Sinon, default s'il existe.
  4. Sinon, pour un switch exhaustif (possible seulement après une compilation séparée, comme une nouvelle sous-classe), une MatchException est levée. Pour un enum, c'est aussi une MatchException depuis Java 21.
Règle · dominance

Une étiquette est dominée si une étiquette précédente correspond à toutes les valeurs qu'elle accepterait. C'est une erreur de compilation : case Rectangle r avant case Carre c rend la seconde inaccessible. Un motif gardé ne domine rien ; un motif non gardé domine les motifs gardés du même type placés après.

§14.11.2Le bloc d'une instruction switch

Dans une instruction switch, chaque règle doit avoir pour corps une instruction-expression, un bloc ou un throw (pas une simple valeur, contrairement à la switch expression). Le type du sélecteur doit être char, byte, short, int, une enveloppe, String, un enum, ou n'importe quel type référence (avec motifs). Avec la preview de Java 27, aussi long, float, double et boolean. Les constantes de case doivent être distinctes et compatibles avec le type du sélecteur.

§14.11.3Exécution d'une instruction switch

Le sélecteur est évalué une fois. Avec des règles, seule la règle choisie s'exécute. Avec des groupes, on exécute à partir de l'étiquette choisie toutes les instructions suivantes du bloc, jusqu'à la fin ou un break. Un break sans étiquette termine le switch. Il est interdit de « tomber » dans un groupe qui déclare des variables de motif.

§14.12L'instruction while

while (cond) S évalue la condition, exécute S si elle est vraie, et recommence. Une terminaison abrupte de S (§14.12.1) : break sans étiquette sort de la boucle (normalement) ; continue sans étiquette passe à l'évaluation suivante de la condition ; une étiquette qui vise ce while a le même effet ; toute autre raison termine le while abruptement.

§14.13L'instruction do

do S while (cond); exécute S au moins une fois, puis teste la condition. Mêmes règles de terminaison abrupte (§14.13.1).

§14.14L'instruction for

§14.14.1Le for basique

for (init; cond; maj) S : l'initialisation (§14.14.1.1) déclare des variables locales d'un même type, ou exécute des instructions-expressions séparées par des virgules. Puis à chaque itération (§14.14.1.2) : condition (absente = vraie), corps, mise à jour. continue saute à la mise à jour, pas à la condition (§14.14.1.3).

Java
for (int i = 0, j = 10; i < j; i++, j--) { }    // deux variables, deux mises à jour
for (;;) { if (fini()) break; }                 // boucle infinie explicite
for (int i = 0, long j = 0; ; ) { }             // ERREUR : un seul type dans l'initialisation

§14.14.2Le for amélioré

L'expression doit être un tableau ou un Iterable. La spec définit le sens par une traduction :

Java
for (String s : liste) traiter(s);
// signifie :
for (Iterator<String> it = liste.iterator(); it.hasNext(); ) {
    String s = it.next();
    traiter(s);
}
Java
for (int x : tableau) somme += x;
// signifie :
int[] a = tableau;                        // évalué une seule fois
for (int i = 0; i < a.length; i++) {
    int x = a[i];
    somme += x;
}
Java
for (String s : liste) if (s.isEmpty()) liste.remove(s);   // ConcurrentModificationException
liste.removeIf(String::isEmpty);                            // la bonne façon

for (int x : tableau) x = 0;                               // ne modifie PAS le tableau : x est une copie

List<Integer> nombres = Arrays.asList(1, null, 3);
for (int n : nombres) { }                                   // NullPointerException : unboxing de null

§14.15L'instruction break

break; sort du switch, while, do ou for le plus proche. break L; sort de l'instruction étiquetée L, qui peut être n'importe quelle instruction (même un simple bloc). Un break ne peut pas sortir d'une lambda, d'une méthode, d'un initialiseur ou d'une switch expression. Les blocs finally traversés s'exécutent, et peuvent annuler le break.

§14.16L'instruction continue

continue; termine l'itération en cours de la boucle la plus proche ; continue L; celle de la boucle étiquetée L, qui doit être une boucle.

Java
lignes:
for (String ligne : texte) {
    for (char c : ligne.toCharArray()) {
        if (c == '#') continue lignes;     // ligne de commentaire : passer à la ligne suivante
        if (c == '!') break lignes;        // fin du traitement
    }
    traiter(ligne);
}

§14.17L'instruction return

return; termine une méthode void, un constructeur (dans l'épilogue seulement), ou une lambda à corps bloc sans valeur. return e; renvoie une valeur, qui doit être affectable au type de retour (contexte d'affectation, §5.2). return est interdit dans un initialiseur, et ne peut pas sortir d'une switch expression.

§14.18L'instruction throw

throw e; évalue e, qui doit être de type Throwable (ou sous-type) ; si la valeur est null, une NullPointerException est levée à sa place. Les exceptions vérifiées levées doivent être gérées (§11.2).

§14.19L'instruction synchronized

synchronized (expr) { … } acquiert le moniteur de l'objet désigné (null lève NullPointerException), exécute le bloc, puis le libère, même en cas de terminaison abrupte. Les moniteurs sont réentrants : un thread peut reprendre un verrou qu'il détient déjà (§17.1).

Java
private final Object verrou = new Object();   // verrou privé : personne d'autre ne peut le prendre
void ajouter(String s) {
    synchronized (verrou) { liste.add(s); }
}
synchronized ("constante") { }                 // à éviter : les chaînes internées sont partagées partout

§14.20L'instruction try

Une instruction try a un bloc, puis des clauses catch et/ou un finally, ou des ressources. Chaque catch déclare un paramètre d'exception, éventuellement de plusieurs types (catch (A | B e), implicitement final).

§14.20.1Exécution de try-catch

Si le bloc se termine normalement, rien d'autre ne se passe. S'il lève une exception V, la première clause catch dont le type peut recevoir V est choisie, V est affecté à son paramètre et son bloc s'exécute. Si aucune ne convient, le try se termine abruptement avec V.

§14.20.2Exécution de try-finally et try-catch-finally

Le finally s'exécute toujours. Le résultat final dépend de la façon dont se terminent le try (ou le catch exécuté) et le finally :

Le try / catch se termine…finally normalfinally abrupt (return, throw, break…)
normalementnormalabrupt, raison du finally
par return vrenvoie v (calculée avant le finally)raison du finally : le return v est oublié
par une exception non attrapée EE est propagéeraison du finally : E est perdue
Java
int f() {
    int x = 1;
    try { return x; }       // la valeur 1 est déjà calculée et mise de côté
    finally { x = 2; }      // modifie x, pas la valeur renvoyée
}                           // f() == 1

int g() {
    try { throw new RuntimeException(); }
    finally { return 2; }   // g() == 2, l'exception disparaît
}

§14.20.3try-with-resources

Chaque ressource est une variable initialisée (ou, depuis Java 9, une variable existante final ou effectivement finale) dont le type implémente AutoCloseable. Les ressources sont fermées automatiquement, dans l'ordre inverse de leur initialisation, que le bloc se termine normalement ou non. Une ressource null n'est simplement pas fermée.

Java
try (var in = Files.newBufferedReader(src);
     var out = Files.newBufferedWriter(dst)) {
    in.transferTo(out);
}
Java · pour une ressource
{
    final var in = Files.newBufferedReader(src);
    Throwable primaire = null;
    try {
        /* bloc, avec la ressource suivante imbriquée de la même façon */
    } catch (Throwable t) {
        primaire = t;
        throw t;
    } finally {
        if (in != null) {
            if (primaire != null) {
                try { in.close(); }
                catch (Throwable fermeture) { primaire.addSuppressed(fermeture); }   // exception supprimée
            } else {
                in.close();
            }
        }
    }
}

Un try-with-resources qui a aussi des catch ou un finally est traduit en un try-with-resources de base imbriqué dans un try ordinaire. Conséquence : les ressources sont déjà fermées quand les catch et le finally s'exécutent.

Java
try (var c = ouvrir()) { … } catch (IOException e) { … } finally { … }
// signifie :
try {
    try (var c = ouvrir()) { … }     // c est fermée ici
} catch (IOException e) { … }         // attrape aussi les exceptions de ouvrir() et de close()
finally { … }

§14.21L'instruction yield

yield v; fournit la valeur d'une switch expression depuis un bloc ou un groupe d'instructions (§15.28). Il ne peut pas traverser une lambda, une méthode ou une autre switch expression. yield est un mot-clé contextuel : pour appeler une méthode nommée yield, il faut la qualifier (this.yield()).

Java
int nbLettres = switch (jour) {
    case LUNDI, VENDREDI, DIMANCHE -> 6;
    case MARDI -> 5;
    default -> {
        int n = jour.toString().length();
        yield n;                      // valeur du bloc
    }
};

§14.22Instructions inaccessibles

C'est une erreur de compilation qu'une instruction ne puisse pas être exécutée parce qu'elle est inaccessible. La spec le définit par une analyse de flux conservatrice, fondée sur la notion « peut se terminer normalement ». Quelques règles :

  • une instruction qui suit return, throw, break, continue ou yield dans le même bloc est inaccessible ;
  • while (true) sans break qui le vise ne peut pas se terminer normalement : ce qui suit est inaccessible ;
  • le corps de while (false) est inaccessible (erreur) ;
  • un catch d'exception vérifiée que le try ne peut pas lever est inaccessible (§11.2.3).
Règle · l'exception du if

if (false) { … } n'est pas une erreur, même si le bloc est inaccessible. Ce traitement spécial permet la compilation conditionnelle avec une constante : static final boolean DEBUG = false; if (DEBUG) log(…);. Le compilateur peut même omettre le code.

Java
while (true) { travailler(); }
nettoyer();                  // ERREUR : inaccessible

while (false) { f(); }       // ERREUR : corps inaccessible
if (false) { f(); }          // OK : compilation conditionnelle

int k = 0;
while (k < 1) { }            // OK : la condition n'est pas une expression constante
return; System.out.println();  // ERREUR

§14.30Motifs

Un motif décrit un test à effectuer sur une valeur, et des variables à extraire si le test réussit. Les motifs apparaissent après instanceof (§15.20.2) et dans les étiquettes case.

§14.30.1Les sortes de motifs

MotifFormeExemple
Motif de typeun type et un nom de variable (ou var en position imbriquée)String s
Motif d'enregistrementun type record et une liste de motifs pour ses composantsPoint(int x, var y)
Motif sans nom_, correspond à tout, ne déclare rien (Java 22)Point(int x, _)
Java
sealed interface Expr permits Nombre, Somme, Produit, Neg { }
record Nombre(int v) implements Expr { }
record Somme(Expr g, Expr d) implements Expr { }
record Produit(Expr g, Expr d) implements Expr { }
record Neg(Expr e) implements Expr { }

static int eval(Expr e) {
    return switch (e) {
        case Nombre(int v)            -> v;
        case Somme(Expr g, Expr d)    -> eval(g) + eval(d);
        case Produit(Nombre(var v), _) when v == 0 -> 0;          // motif imbriqué, gardé, avec _
        case Produit(Expr g, Expr d)  -> eval(g) * eval(d);
        case Neg(Neg(var inner))      -> eval(inner);              // --x == x
        case Neg(Expr x)              -> -eval(x);
    };                                // exhaustif : pas de default nécessaire
}

if (obj instanceof Somme(Nombre(int a), Nombre(int b)) && a == b) { }

§14.30.2Correspondance de motif

  • Un motif de type T t correspond à une valeur non nulle qui peut être convertie en T par une conversion de test (§5.7). Si le motif est inconditionnel (le type statique de la valeur est déjà un sous-type de T), il correspond à tout, null compris, mais seulement en position imbriquée.
  • Un motif d'enregistrement R(p1, …, pn) correspond à une valeur non nulle de type R dont chaque composant, obtenu en appelant son accesseur, correspond au motif imbriqué. Si un accesseur lève une exception, la correspondance lève MatchException.
  • Au niveau supérieur, null ne correspond à aucun motif : null instanceof String s est faux.
Java
record Boite(Object contenu) { }
Object o = new Boite(null);
o instanceof Boite(Object x);    // true : Object x est inconditionnel pour le composant, null correspond
o instanceof Boite(String s);    // false : String s n'est pas inconditionnel, null ne correspond pas
